## Context

当前系统支持用户上传自定义 DOCX 模板文件来影响转换后的文档样式。前端提供"上传模板"按钮，后端接收 template 参数并应用到转换过程中。

根据用户需求，模板功能不再需要，需要完全移除以简化系统。

## Goals / Non-Goals

**Goals:**
- 移除前端"上传模板"按钮及关联 UI
- 移除前端模板状态管理和处理逻辑
- 移除后端 API 的 template 参数支持
- 简化转换器，移除模板路径处理逻辑
- 保持其他功能不受影响

**Non-Goals:**
- 不修改 Markdown 转换核心逻辑
- 不修改 DOCX 样式渲染逻辑
- 不修改前端编辑器功能
- 不修改导出和打印功能

## Decisions

### 1. 前端修改范围
**决策**: 完全移除模板相关代码，而非仅隐藏按钮
**理由**: 避免遗留无用代码，保持代码整洁

### 2. 后端 API 变更
**决策**: 从 /convert 接口移除 template 参数
**理由**: 既然不支持模板上传，API 不应再接受此参数

### 3. 转换器简化
**决策**: 保留 DocxRenderer 类但移除 template_path 参数支持
**理由**: 未来可能需要扩展其他样式选项，保留类结构更灵活

## Risks / Trade-offs

- **[Risk]** 用户可能已习惯模板功能 → **Mitigation** 用户明确要求移除，无此风险
- **[Risk]** 代码删除后难以恢复 → **Mitigation** 使用版本控制，可随时回滚
- **[Trade-off]** 失去自定义模板能力 → 换取更简洁的用户界面和代码库

## Migration Plan

1. 修改前端 App.vue，移除模板相关代码
2. 修改后端 main.py，移除 template 参数处理
3. 修改后端 converter.py，简化 DocxRenderer 初始化
4. 测试验证转换功能正常
